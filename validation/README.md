# Validation against IPL

The scripts that compared ipldt with Scanco IPL V5.42 on the paper's 137 XtremeCT II scans, and the de-identified
per-scan records they wrote. The records are enough to regenerate every number of the paper
(`python tools/regenerate_paper_numbers.py`); re-running the comparisons themselves needs the scans and IPL's
products, which are not public (see "Running the harness on your own data" below).

## The two configurations

- **A** gives ipldt IPL's own segmentation (SEG, TRAB_SEG, CORT_SEG), compartment masks and rendered contours, and
  tests the distance-transform maps (Tb.Th, Tb.Sp, 1/Tb.N, Ct.Th) and the cortical pore map voxel for voxel.
- **B** gives ipldt only IPL's periosteal contour and runs the whole chain (STEP 1 compartments, contour rendering,
  Laplace-Hamming SEG, pores, distance transforms, metrics); every stage is compared with IPL's product.

Two volumes are compared on the union of their grids by global voxel position; a stage is exact on a scan when no voxel
differs.

## The reference runs

For every scan the reference is IPL's own evaluation of that scan on the scanner, with the parameter set IPL used for
it:

- **Patellae** (21): IPL's evaluation as delivered.
- **Radius and tibia, first set** (`<OSLH_AUTO>`, 63 records): measurements whose delivered evaluation had later been
  corrected by an operator. IPL's automatic run of each was recovered from the scanner's file versions and staged as
  a folder of its own (`stage_automatic_set.py`), so the reference is the automatic run and not the corrected one.
- **Radius and tibia, second set** (`<OSLH_NOEDIT>`, 54 diaphyseal records), each staged at IPL's automatic run
  (`stage_noedit_set.py`): most are staged from the delivered files, which are that run; three that had also been
  re-evaluated with the re-evaluation script are staged from their first, automatic run.
- **Excluded**: Diaphyseal/CKD/991161 is in the first set but is left out of every aggregate: its delivered trabecular
  contour is not the one IPL's own evaluation used, so its products are not a like-for-like reference (the evidence is
  in `validate_dataset.EXCLUDED_IDS`; it is also the only scan IPL segmented with a low-pass cut-off of 0.2 instead of
  0.3). Its record is kept. The 137 scans of the paper are the 21 patellae and the 62 + 54 counted radius / tibia
  records.

## Scripts

| Script | What it does |
|---|---|
| `validate_dataset.py` | the harness for both cohorts (`--dataset oslh` for the radius / tibia scans, `--dataset patella`): configurations A and B, the pore cascade in both, per-scan records, tables and summaries |
| `validate_against_ipl.py` | patella configuration A (the five maps of the 21 patellae); writes `results/against_ipl_run/` by default |
| `validate_from_ipl_contour.py` | patella configuration B, stage by stage; writes `results/from_ipl_contour_run/` by default |
| `patella_bvtv_A.py` | patella configuration-A BV/TV, with IPL's printed sheet value beside it; writes `results/patella_bvtv_A_run/` by default |
| `porosity_AB_stats.py` | pooled pore-map and Ct.Po statistics of both configurations -> `results/porosity_AB_summary_n137.json` |
| `oslh_inventory.py` | inventory of the radius / tibia export (file sets, calibration, study and participant from the scan headers). Its output carries identifiers and is internal only (git-ignored) |
| `stage_automatic_set.py`, `stage_noedit_set.py` | how the two radius / tibia sets were assembled from the scanner's evaluation runs (see "The reference runs"); they read the non-public scanner fetch |
| `datapaths.py` | where the non-public data live (`IPLDT_LAB_ROOT` and the per-location variables) |
| `result_sets.py` | the names of the two radius / tibia result sets the paper is built from |

### Record format

Each record of `validate_dataset.py` holds: `id` (for example `Diaphyseal/CKD/251016`), `tag`, `group`, `base` (the
pseudonymised file identifier of the measurement), `meta` (region, bone, site index, study label), `grey` (grid and element
size), `inputs` (type, dimensions and position of each IPL file used; no paths), `preset` (the STEP-1 parameter set),
`variants` (the evaluation-script variant read from IPL's processing logs), `seg_variant_used` (the SEG assembly order
used; see below), `A` and `B` (per-map mismatch counts, supports, grids, the sparse joint histograms and coordinates of
differing voxels, metrics of both sides, timings), `porosity` (pore maps and Ct.Po in A and B), `inventory` (the
study, a pseudonymous participant code, region, bone, site, the pseudonymised measurement number, the calibration, and `plan.status`,
the inventory's classification of the measurement's delivered export, for example `manual-correction` for the first
set; the record itself is the automatic run), `notes` and `warnings`.

`seg_variant_used.rule` is the `--seg-variant` option of the run. Every published record uses the shipped engine's
assembly order (`periosteal_first`, `seg_variant_used.value`), which is also the order IPL's processing log records for
every one of them. Records whose rule is `best` (for example the 21 of `porosity_AB_patella`) were written with
`--seg-variant best`, a diagnostic that picks the order whose SEG agrees better with IPL's; it picked
`periosteal_first` on every scan, so those records equal a run with the fixed order. The harness defaults to
`periosteal_first`.

### Identifiers and de-identification

The records were written by the harness on the laboratory's data and de-identified for publication by
`tools/deidentify_results.py`: the patient-name field, scan and evaluation dates and times, file paths, file times and
checksums, contour-file timelines, scanner paths and header dumps are removed, and each participant code carried in
the radius / tibia scan headers is replaced by a keyed pseudonym (`<study>-<6 hex digits>`; the key is kept by the
authors). The scan identifiers get keyed pseudonyms from the same key, consistently in file names, records, tables,
figure sidecars, documentation and the comments and tests of the code: the scanner's measurement number of a
radius / tibia record (`<region>/<study>/<measurement>`) becomes six digits, the study's knee identifier of a patella
becomes `PFJ-<6 hex digits>_<L|R>` (both knees of a participant share it) and the scanner's file identifier (`base`)
becomes `X` and seven digits. No scan identifier is kept as it is: the paper prints none (`PRINTED_BY_THE_PAPER` in
the tool is empty, and its `stage` checks that against the paper). The same tool's `verify`
command scans a whole tree for identifiers, vendor material, local paths and references to internal material. The
published harness writes the study label instead of the name and file names instead of paths, but its raw output
should still be treated as internal until it has been through the de-identification.

## Running the harness on your own data

The harness reads one folder per measurement with IPL's exported products. Point it at your data with `--root` or the
variables of `datapaths.py`, and write into a new results folder. The published record folders under `results/` (and
`results/records.json` / `sample_means.csv`) are protected: every script refuses, before writing anything, a
`--results` that is or lies inside one of them unless `--allow-overwrite-shipped` is given.

```bash
python validation/validate_dataset.py --dataset oslh --root <folder> --results validation/results/my_run --subjects Distal/CKD/345857
python validation/validate_against_ipl.py --root <patella folder> --results validation/results/my_patella_A
python validation/validate_from_ipl_contour.py --root <patella folder> --results validation/results/my_patella_B
python validation/patella_bvtv_A.py --root <patella folder> --results validation/results/my_patella_bvtv
```

`python validation/validate_dataset.py --help` lists the options (configurations, back end, Laplace-Hamming variants,
exclusions). The layouts the harness expects are described in its docstring.
